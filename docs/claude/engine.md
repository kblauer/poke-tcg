# Engine: shared helpers and rules for every set

Moved out of CLAUDE.md word for word (2026-10-26) so it loads only when needed. Everything here is still agreed with the user and binding.

## Shared helpers (from the #99 code review, PRs #101–#107, merged 2026-10-24)
Issue #99 (https://github.com/kblauer/poke-tcg/issues/99) was a whole-codebase review: its bugs were places the code didn't apply a rule it already had, mostly a check done by hand in one file while a helper existed elsewhere. Use the helper; never re-implement one of these inline. README: Performance has the measurements.
- Engine, rules checks:
  - Energy leaving the opponent's Pokémon: discards through `energyCanGo` / `discardDefenderEnergy` (Brock's Protection, Unown K's Keep, Ecogym via `discardTheirEnergy`); moves to another Pokémon, the hand or the deck through `energyCanMove` (`effects/common.ts`). Trainers that reach an Active Pokémon check `trainerProof` and `energyProtected` (Gust of Wind in `base1-trainers.ts` is the model; Pow! Hand Extension was missing both).
  - Special Conditions given outside an attack (powers, bodies, Trainers, between-turn effects) go through `afflictionBlocked` (engine.ts): one check for `conditionProof`, `conditionFree`, `noPoison`, `conditionBarred`, Flash Touch, Pollen Shield, an attack's `conditionProof` effect and a run's `conditionGuard` rule. Attacks' `inflict` does the same itself. Never hand-roll a subset.
  - Curing: `clearSpecialConditions` (status.ts: condition, poison, burned, `paralyzedTurn`); checking: `hasSpecialCondition`. Never `Object.assign(p, { condition: null, … })`.
  - Poké-Bodies and copying powers (Psylink, Mimic, Psymimic, Fellowship, Versatile, Empty Shell, Rebirth) are checked with `powerActive` and `effectId`, never `!p.condition` or `powerEffect(defId)`; `usableAttacks` takes `sides` (both players) so they see Goop Gas, auras, Imprison and Ancient Wind; pass it wherever you have both sides.
  - Types with `hasType`/`typesOf` (Kecleon, printed dual types), never `=== 'water'`; `applyWeaknessResistance` takes `typesOf`, never one type. Energy types with `isEnergyCardOf`/`energyProvided`/`counts`/`payCost`, never `energyType` comparisons (Rainbow, converted, Crystal).
  - Named Pokémon with `namesMatch`, never `name === 'Magnemite'` (Dark, Light, δ and owners' variants reach every run, since any deck starts any run). Evolution checks with `evolvesOnto` (Blissey ex's `alsoEvolvesFrom`, Buried Fossil); stages and Basics with `inPlayDef` (`asBasic` fossils, Transformed Ditto).
  - Bench room with `openBenchSlot`/`benchRoom` (Narrow Gym), never `bench.indexOf(null)`; `benchSearch` in `common.ts` is the model for Call for Family and its like.
- Engine, shared code: `opponentOf` and `newInPlay` (engine.ts), `pokemonAt` (powers.ts) / `atTarget` (trainers.ts) for "the Pokémon at a target", `effects/common.ts` for what effects share (`POKE_BODY`, `onlyActive`/`onlyBenched`, `targetOf`, `energyCards`/`basicEnergyOn`, `damageOpponent`/`opponentTargets` (`damageOpponent` skips Weakness and Resistance on the Active Pokémon too, for the WOTC wording; the later sets' "Don't apply Weakness and Resistance for Benched Pokémon" is `damageChosen`, Weakness and Resistance on the Active one), `inPlay`, `same`). Cross-set table reads (one set's attack reusing another's) always go through `same(() => …)`, never an eager `BASE1['…']!` at module load (the tables aren't filled yet; it only worked for import leaves); an effect two sets share with its own `text` is an exported const in the first set (`amnesia`, base1.ts). A table is a single literal, never mutated after definition (an alias is a second key). In `resolveSkyridge`, "restore the choice, then error" is `retry(choice, message)`. `barriers` (attacks.ts) stays as separate blocks on purpose: they aren't uniform. Only symbols another file uses are exported; a file-local helper stays unexported.
- Engine, performance (agreed in #106): `cloneState` copies a state but shares `state.cards`, so nothing may mutate the card library after `createGame` (only `applyDebug` replaces it with a new object; a test plays a game on a frozen library). Every CPU decision runs inside `withAttackMemo` (`cpu/shared.ts`), which memoises `attackOptions` by state for the decision's length, so a state must never be changed in place while a decision runs (tests may change states between runs). The view's `attackDamage` is memoised per state (view.ts). Keep these when adding CPU steps or view fields.
- Campaign: `isBattleEncounter` (a type guard), never `as BattleEncounter`; `routeAt(type, position)` (run-types.ts) for which map a step is on (RouteView keeps its own clamp to `gymStart`); any re-roll of a step's options (Repel) passes `poolAt(...)` like `createRun`, or the global `TRAINERS` list leaks Swimmers onto land; `isBattleKind`/`isBossKind` for the kinds of battle; one `Boss` type (`import type` from bosses.ts); `KANTO/JOHTO/HOENN_BOSS_ROOMS` are `Record<<Region>BossId, Route>` so a missing room fails to compile (the `tools/routes/…` generators emit the same typing); the boss decks' basic Energy ids come from pool.ts's `GEN2/GEN3_BASIC_ENERGY`; `GEN2_DONE_SETS = GEN2_SETS`. A step's `pick()` must never get an empty list (the trade asks for any card when the deck has none from the pool). A debug-skipped battle must not tick a consumable's `battlesLeft`. Boss ids aren't renamed (saved runs hold them). `deckErrors` (campaign) can't import shared's `deckProblems`: shared depends on campaign.
- API: `catalogRows` (`cards.ts`) is the catalog, loaded once per instance; `cards.list` is served from it with `Cache-Control` (app.ts) and `deck-text.ts` matches against it; never `findMany()` the whole Card table in a request. Errors are `TRPCError`s with the agreed codes (BAD_REQUEST for an unknown card, NOT_FOUND for another's or a missing row, CONFLICT for a stale version, INTERNAL_SERVER_ERROR for impossible states), never a plain `Error`. `run.shop` is a query that writes `Run.shop` once (documented, not changed). The pure part of settling a battle is `battleOverAction` (tested).
- Web: one `RunProvider` (in the layout, inside the router) and `useRun()` reads it; never a second `useRunControl`. Pages show an error only when there's nothing to show (`if (error && !data)`), otherwise a toast: a transient refetch error must never unmount the board. Escape with `useEscape` (`hooks/useEscape.ts`), never a new keydown listener. Button and dialog classes from `utils/styles.ts` (`BUTTON`, `CHOICE_BUTTON`, `OPTION_BUTTON`, `PAGE_BUTTON`, `ICON_BUTTON`, `DIALOG_BACKDROP`, `DIALOG`); off-board card thumbnails from `utils/layout.ts` (`CARD_THUMB_XL`…`XS`, `RUN_CARD`); right-click inspect with `useInspectOnRightClick({ clearsPreview: true })`. Deck tiles read the catalog from `CatalogContext` and locks from `useUnlocked()`, never props threaded down. Window listeners added in effects have a dependency array and are removed on unmount; drags use pointer capture. Pages are lazy (`lazyRouteComponent` in main.tsx), as are `PackOpening`, the audio player and `CardInspector` with the holo styles; the rules engine loads only with the battle page, so nothing outside it may import from the engine's effects, and labels the campaign needs (`typeName`) live in the engine's `cards.ts`, not `attacks.ts`. The workspace packages are `sideEffects: false`: no module-level side effects. Splits from #105: `RouteView.tsx` → `utils/routeFigures.ts`, `hooks/useWalk.ts`, `hooks/usePan.ts`, `components/run/RouteSprites.tsx`; `components/phone/PhoneBoard.tsx` owns the phone board; `AccountNameField.tsx` and `run/RunDeckPanel.tsx` are the renamed files (`LogDrawer.tsx` keeps its name). `Board.tsx`'s `playerSlot`/`cardPanel` and the six centred dialogs were left (they differ; no `Modal` was extracted).
- Open decisions from #99, flagged for the user and not changed: the final boss gives no card reward (`run.test.ts` asserts it); `energyEvolution` runs after `ok()` (engine.ts); the passive CPU attaches only Energy of a type its Pokémon has (Double Colorless and Rainbow never); the CPU concedes when it throws; Repel on a required-battle step can turn it into a non-battle encounter (the step isn't marked required in `RunState`); trainers.ts's `isEnergyCardOfType` (Soak Up) reads the card as printed, ignoring `converted`/`windless`; Thick Skinned blocks Burned (`conditionFree` covers every condition); a debug-skipped gym leader battle grants the badge; 13 buttons styled `bg-slate-700 hover:bg-slate-600` are off the agreed `bg-slate-600 hover:bg-slate-500` (listed in #103); `useEscape` has no test (it would need `@testing-library/react`). The shared DB was re-seeded 2026-10-24 (`HOLO_ENERGY_SETS`: holo Energy in every pack set), so the test pool's `exEvolving` can go.

## Engine-wide rules
- CPU difficulties live in `packages/game-engine/src/cpu/`, one file each (`passive.ts`, `trainer.ts`, `gym-leader.ts`) plus `shared.ts` and `evaluate.ts`. Keep them separate. Gym leader is the baseline the user agreed on (README: The CPU opponent); change the difficulties' rules only with the user's say-so. Agreed (2026-10-24): the Trainer and gym leader CPUs never use an attack that could lose them the game, in any coin-flip outcome (`loseChance`, `safe` in `cpu/shared.ts`); not losing comes before damage. Agreed (2026-10-20): the gym leader plays every card: hand-written rules first, then the generic judgement (`evaluate.ts`: moves tried on imagined copies, never peeking at draws or flips, the position scored from what it can see). The Trainer CPU plays only its short list (`TRAINER_CPU_PLAYS`, `TRAINER_CPU_ENERGY`), enough for each generation's random decks, which hold only cards it plays (`generateDeck`'s `difficulty`); the gym leader's random decks add disruption. A new Trainer for Trainer CPU decks must go in both lists (a campaign test checks).
- General rules (agreed 2026-10-20, every set): Confusion is the modern rule (tails on attacking: 30 damage to itself; a Confused Pokémon retreats with no flip). Every Pokémon Power stops with any Special Condition, Poisoned and Burned included, also the older cards printed "Asleep, Confused, or Paralyzed" (`hasSpecialCondition`, in `powerActive`, `powerError`, Toxic Gas and the powers that check it themselves); only Fossil's Transparency stops only while Asleep (`stopsOnlyWhileAsleep`), and powers printed to work anyway have `ignoresConditions`.
- The same-card rule (agreed 2026-10-25, every set; README: Game engine): a pick among cards that are all the same card (same name, attached the same way: `sameCards`, status.ts) is made for the player, asked only when they differ; exact counts at once, "up to" picks and searches take the most, "as many as you like" discards and "may" choices still ask. A new question offering cards must go through the layers' `autoAnswer` or be a kind in engine.ts's `SAME_CARD_TAKES`/`SAME_CARD_MUSTS` (`sameCardAnswer`, run by `applyAction`); never "the first that fits" when the cards can differ (Gen 4's `discardOwnEnergy`/`removeDefenderEnergy`, effects/dp1.ts). Test decks of identical cards answer themselves: give a test a second, different card to see the question.
- Missing rules: card effects for later sets. Attacks where the opponent chooses a benched Pokémon ask them once the attack is over (a `PendingChoice` for the defending player, via `ctx.opponentChooses`; the turn ends after it). Switching (Whirlwind, Ram, Terror Strike, Rapid Spin, Fling) uses `opponentSwitches`, and the CPU brings in what it would promote. Cat Punch's damage goes through `damageChosenBenched`, so it still counts as the attack's (Defender, Kabuto Armor, bench protection), and the CPU picks the benched Pokémon with the most HP left. With one benched Pokémon there's no question. Jungle is done (`effects/jungle.ts`, `jungle-powers.ts`, `jungle-trainers.ts`); the gym leader CPU plays every card, the Trainer CPU its short list. Fossil is done (`effects/fossil.ts`, `fossil-powers.ts`, `fossil-trainers.ts`). The Wizards Black Star Promos are done (`effects/promos.ts`, `promos-powers.ts`, `promos-trainers.ts`, rulings in their header comments).
- A `PendingChoice` can belong to the player whose turn it isn't (Computer Error, Chain Reaction). `applyAction` takes `RESOLVE_CHOICE` from that player only, and every CPU difficulty answers its own pending choice before checking whose turn it is. New choices that the CPU can be asked must be handled in `resolveSearch` (`cpu/shared.ts`) and `finishSearch` (`cpu/passive.ts`).
- Stadiums: `GameState.stadium` (one for both players), played like any Trainer with `stadium: true` on its effect; `useStadium` makes it usable once a turn with `USE_STADIUM`. Baby Pokémon are `baby: true` on the card (the API sets it from the "Baby" stage and for the promos TCGdex lists as Basic).
- TCGdex card text drops energy icons ("Discard 1 Energy card" for "Discard 1 Fire Energy card"). Check the printed card for any untyped Energy in an effect and store the printed wording as `text`.
- In-play Pokémon: use `inPlayDef`/`effectId` (status.ts), not `lookupCard(cards, p.card.defId)`, for anything rules-related, so a Transformed Ditto works. Check passive powers with `powerActive`, which handles Toxic Gas.
